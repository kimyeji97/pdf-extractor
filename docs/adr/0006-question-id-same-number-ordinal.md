# ADR-0006 · 문항 식별자에 "같은 쪽·같은 번호 안 순번 k"를 항상 붙인다

> 상태: 채택 · 날짜: 2026-09-29 · 출처: [PLAN-B20-invisible-number-and-id-collision](../plans/PLAN-B20-invisible-number-and-id-collision.md) · 대체: [ADR-0002](0002-question-id-composite-key.md)

## 맥락

ADR-0002는 자동 문항을 `{job_id}:{쪽}:{번호}`로 식별했다. 이 키는 "한 쪽에 같은 번호는 하나뿐"이라는 전제 위에 서 있었다.
실제로는 문항을 찾는 곳이 `question_id` 문자열이 아니라 `(쪽, 번호)`다. PDF 생성은 "그 쪽에서 그 번호의 첫 경계"를 쓰고,
문항 썸네일 캐시는 `q_{쪽}_{번호}.png`, 제목 수정·삭제·썸네일·벌크 삭제 API는 경로나 본문의 번호로 문항을 찾는다.

REQ-B18이 경계를 번호가 아니라 **위치**로 병합하면서 전제가 깨졌다. 한 쪽에 같은 번호가 둘 공존하게 됐기 때문이다. 내신마스터에서는
"유형 01" 제목과 문항 "1."이 같은 쪽에 5쌍 공존한다. 그 결과 둘이 같은 썸네일로 보이고, 생성·삭제는 둘을 구분하지 못한다. 공존은
B18의 목적(진짜 문항을 번호 충돌로 잃지 않기)의 결과라서 없앨 수 없다. 식별이 공존을 견뎌야 한다.

저장된 문제집(편집 복원용 선택)에는 옛 형식 ID와 `question_num`이 남아 있다. 재감지는 감지 코드가 바뀔 때마다
(B13·B16·B18·B20) 좌표를 조금씩 움직인다.

## 결정

자동 문항 식별자를 **`{job_id}:{쪽}:{번호}:{k}`**로 한다. `k`는 같은 쪽·같은 번호의 경계를 위에서부터 센 순번(0부터)이고, 공존이 없어도
**항상 붙인다**(대부분 `k=0`). 수동 문항(`…:manual:{uuid}`)은 그대로다.

**호환 규칙은 하나로 통일한다: `k`가 없으면 `k=0`.**
- 옛 형식 ID와 저장된 선택은 읽을 때 `k=0`으로 해석하고, 저장 데이터는 고치지 않는다.
- 번호로 지목하는 API는 쿼리 `?k=`를 받는다(생략 시 0). 벌크 삭제는 `(번호, k)` 쌍을 받고 옛 `question_nums`는 `k=0`으로 읽는다.
- 썸네일 캐시 키는 `k=0`이면 옛 이름 `q_{쪽}_{번호}.png`를 그대로 쓰고, `k≥1`이면 `q_{쪽}_{번호}_{k}.png`를 쓴다.

`k=0`은 지금 동작("그 쪽 그 번호의 첫 경계")과 같아서 옛 데이터·옛 URL의 결과가 바뀌지 않는다.

## 기각한 안

- **y 좌표(반올림)를 넣기** (`…:{번호}@{y}`) — 위치가 값에 직접 드러나지만, 감지 코드가 바뀌어 `y_top`이 몇 pt만 움직여도 ID가 바뀌고 저장된
  문제집 선택이 풀린다. / **재검토 조건**: 경계 좌표가 감지 버전과 무관하게 고정되는 저장 구조(예: 문항 좌표를 사용자가 확정해 저장)가 생기면
- **쪽 안 전체 순번** (그 쪽 모든 경계를 번호와 무관하게 0,1,2…) — 위쪽에 경계가 하나만 늘어나도(목차·제목이 새로 잡히는 경우) 그 아래
  모든 ID가 밀린다. / **재검토 조건**: 번호 없는 문항(유제 등)을 식별해야 해서 번호 축을 쓸 수 없게 되면
- **겹칠 때만 접미사** — 기존 ID를 거의 그대로 두는 장점이 있었지만, 겹침 여부에 따라 같은 문항의 ID 형식이 재감지마다 바뀔 수 있다(사용자 기각).
  / **재검토 조건**: 식별자 형식 변경 비용(프론트·저장 데이터)이 이 결정보다 커지는 경우
- **바꾸지 않기(B20 범위 밖)** — 공존 쌍이 계속 같은 썸네일로 보이고 생성·삭제가 둘을 구분하지 못한다. / **재검토 조건**: 해당 없음(버그 방치)
- **question_id를 경로로 쓰는 API** (`…/questions/by-id/{question_id}`) — 식별자 하나로 통일되지만 job·쪽이 경로와 ID에 중복되고 기존 라우트
  체계와 따로 논다. / **재검토 조건**: API를 전면 개편할 때

## 결과

- 같은 쪽·같은 번호의 경계가 **위쪽에** 새로 생기면(감지 규칙 변경으로 제목이 새로 잡히는 경우) 아래 문항의 `k`가 1 밀린다. 저장된
  문제집에서는 그 선택이 다른 경계를 가리키게 된다. 좌표 흔들림에는 강하고, 위쪽 공존 변화에는 약하다.
- 옛 문제집에 저장된 공존 쌍의 선택은 지금처럼 `k=0`(위쪽 경계)을 가리킨다. 내신마스터처럼 위쪽이 제목인 경우 옛 문제집을 다시 생성하면
  제목이 크롭될 수 있다. 사용자가 편집 화면에서 다시 골라야 고쳐진다.
- 공존이 있던 쪽은 재감지 전까지 `k=0` 썸네일로 옛 이미지가 남을 수 있다(재감지 prewarm이 덮어쓴다).
- 프론트는 `k`를 들고 다녀야 한다(목록 응답 → 선택·삭제·썸네일 URL).
