# PLAN-28 · 분석 결과를 다른 계정에 공유

> 출처: 2026-10-19 세션 (공유 기능 검토) · 작성: 2026-10-20 · 상태: ✅ 완료 (2026-10-22 · PR #49·#50 · 리뷰 회차 3)

## 배경

실사용에서 분석과 생성이 사람 단위로 갈렸다. a가 PDF를 분석하고, b·c·d가 그 분석 결과로 문제집을 만든다.

지금은 모든 데이터가 `owner_id` 한 사람에게만 보인다. b는 a의 분석을 볼 수 없어서 같은 PDF를 다시 올려 다시 분석해야 한다.

생성 담당자는 문제집을 만들다가 미탐을 발견하기도 한다. 이때 분석을 고칠 권한이 없으면 a에게 부탁하고 기다려야 한다.

## 범위

**포함**
- 분석 결과(SOURCE job)를 다른 계정에 공유하고 해제한다
- 역할 3종: 소유자 · 편집자 · 뷰어
- 공유받은 분석이 목록에 보이고, 그 분석으로 문제집을 만들 수 있다
- 역할에 따라 쓰기 API를 막고, 화면에서 편집 컨트롤을 숨긴다

**제외**
- 생성 문제집 공유. 원래 REQ-28은 "분석 파일·생성 문제집" 공유였다. 실제로 필요한 흐름은 분석 결과를 같이 쓰는 것뿐이라 이번에는 뺀다(2026-10-19 검토)
- 권한 요청·승인 흐름. 생성 담당자가 편집하려면 요청하고 기다리는 구조가 사용자가 걱정한 불편 그 자체다. 생성 담당자는 처음부터 편집자로 공유한다(2026-10-19 검토)
- 표지·각주·워터마크·템플릿 공유. 이번 요구에 없다

## 제약·함정

- 계약 #30: 판정 함수를 바꾸면 그 라우터를 부르던 기존 테스트가 한꺼번에 영향받는다. `authed_client`(admin)로 원래 의도를 유지한다
- 계약 #31: `<img src>`·react-pdf가 직접 여는 URL은 헤더를 못 붙인다. 쿠키 인증 경로도 새 판정을 거치는지 따로 확인한다. 테스트 클라이언트는 헤더를 붙여서 녹색으로 지나간다(B15)
- 계약 #32: `owner_id`가 None인 옛 레코드는 admin만 본다. `shares`가 있어도 이 규칙을 바꾸지 않는다
- 계약 #34: 공유받은 사람이 조회해도 감지를 돌리거나 상태 파일을 쓰지 않는다
- 계약 #16: 문항 ID는 `{job_id}:{page}:{num}:{k}`. 공유받은 사람의 selections도 원본 `job_id`를 그대로 쓴다
- Phase 3 잠금은 프로세스 안에서만 유효하다. ECS 태스크나 uvicorn 워커를 2개 이상으로 늘리면 잠금이 깨진다. 늘릴 때 다시 본다
- 계약 #27: 알림 수신자가 늘어도 기준선 규칙은 그대로다. 공유받은 순간 a의 지난 30일 알림이 b의 피드에 한꺼번에 들어온다. 이게 스낵바로 쏟아지지 않는지 Phase 4에서 확인한다
- 공유 인덱스는 상태 파일과 따로 산다. job 삭제 때 인덱스의 그 job 항목도 지운다
- 렌더 무대 없는 화면(`work.jsx`·`editor`)을 고치면 `npm run build`를 따로 돌린다
