# PLAN-B15 · 이미지 요청 401 — `<img>`가 인증 헤더를 못 보냄 (쿠키 병행)

> 출처: 현재 세션(2026-09-28 dev 배포·admin 승격 직후) · 작성: 2026-09-28 · 상태: ✅ 완료 (Phase 1~3 2026-09-28)

## 배경

REQ-27 Phase 2가 이미지 엔드포인트에도 `get_current_user`(= `Authorization: Bearer` **헤더**만 봄)를
걸었다. 그런데 프론트는 이 URL을 `<img src>`에 그대로 넣고, **브라우저의 `<img>` 요청은 커스텀 헤더를
붙일 수 없다.** 그래서 로그인 상태에서도 이미지가 전부 401이다.

- 영향 엔드포인트 5개: `browse.py:551`(페이지 썸네일) · `:1122`(문항 썸네일) · `:1180`(수동 문항 썸네일) ·
  `cover.py:81`(표지 이미지) · `watermark.py:83`(워터마크 이미지)
- 로컬 모드(`STORAGE_BACKEND=local`) 전용 `/api/files/{key}`(`upload.py:222`, PDF 뷰어·결과 다운로드)도
  같은 이유로 막힌다. dev(s3)는 R2 URL을 직접 쓰므로 영향 없음
- 발견: 2026-09-28 dev 배포(ECS rev 4 + 프론트 재배포) → admin 승격·백필 뒤 사용자 육안 확인.
  목록·이력 **데이터는 보이고 이미지만** 401
- 테스트가 못 잡은 이유: 기존 케이스는 헤더를 붙이는 `authed_client`로 부른다(계약 #30).
  **"헤더 없이 쿠키만 있는 요청"이라는 브라우저 `<img>` 조건을 재현하는 케이스가 없다**

## 범위

**포함**
- 로그인·토큰 갱신 응답에서 access token을 **HttpOnly 쿠키**로도 심는다 (localStorage·헤더 경로는 그대로 — 병행)
- 이미지·파일 GET 6개(썸네일 3종·표지·워터마크 이미지·`/api/files`)에 한해 헤더가 없으면 쿠키를 읽는다
- 로그아웃 시 쿠키 삭제 — 현재 로그아웃은 클라이언트 전용(`_clearTokens`)이라 HttpOnly 쿠키를
  JS가 못 지운다. **서버 로그아웃 엔드포인트가 새로 필요하다**
- 프론트의 로그인·refresh·로그아웃 fetch에 `credentials: 'include'` — 교차 출처 응답의 `Set-Cookie`를
  브라우저가 저장하려면 필요하다
- 회귀 케이스: 헤더 없이 쿠키만으로 이미지 엔드포인트 200 / 쿠키·헤더 둘 다 없으면 401

**제외**
- 이미지 URL 형태 변경 — 계약 #15(결정적 썸네일 URL) 유지가 이 안을 고른 이유다
- localStorage 토큰 제거(쿠키 단일화) — 이번엔 `<img>` 401만 닫는다. 헤더 경로는 건드리지 않는다
- 표시 방식 변경(`<img>` → blob) — 기각안(아래 결정)
- 쿠키 인증을 이미지·파일 GET 밖(POST/DELETE 등)으로 넓히기 — CSRF 표면(아래 결정)
- B15 배포 전 로그인 세션의 쿠키 동기화 코드 — 재로그인으로 해결(아래 결정)

## 제약·함정

- **계약 #31 재발 형태** — "헤더를 자동으로 못 받는 호출"이 raw fetch만이 아니라 **`<img>`·`<a href>`·react-pdf
  URL 로딩**에도 있다. 인증을 새로 거는 엔드포인트가 브라우저 태그로 직접 소비되는지 확인해야 한다.
  완료 후 계약 승격 후보
- **계약 #15** — 썸네일 URL은 결정적이어야 한다. URL에 토큰·서명을 섞지 않는다
- **계약 #26** — 로그아웃 서버 호출을 추가할 때 `apiFetch`의 전역 딤 여부를 의식할 것
- **알려진 한계** — B15 배포 전에 로그인한 세션은 재로그인 전(최대 1시간)까지 이미지 401 (결정 표)
- 교차 출처 fetch에서 `credentials: 'include'`를 빠뜨리면 **`Set-Cookie`가 에러 없이 무시된다** — 응답은
  200으로 보이고 이미지만 계속 401이다. "조용히 틀리는" 계열(계약 #18·#20·#29)
- 자동 테스트는 `authed_client`(헤더)만 써 왔다 — 쿠키 경로 케이스는 **헤더를 붙이지 않는 클라이언트**로 써야
  이 버그를 재현한다
