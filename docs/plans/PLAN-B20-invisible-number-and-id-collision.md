# PLAN-B20 · HWP 출력 PDF가 전부 오탐 — 보이지 않는 번호 글자 + 같은 쪽·같은 번호 식별자 충돌 (B18 회귀)

> 출처: 2026-09-29 세션(dev `테스트02` 육안 제보 + 스크린샷 4장 → 원인 조사, AskUserQuestion 결정 3건) · 작성: 2026-09-29 · 상태: 🟡 진행 (Phase 1·2 완료 · PR #23 main 머지 `0d8c5d4` · Phase 3·4 완료 2026-09-29 — Phase 5 dev 확인 남음)

## 배경

dev `테스트02`(`2026 P-Math 미적분1 Red_인쇄용 (HWP2005).pdf`, 198쪽)를 재감지하자 거의 모든 쪽에서 **보이는 진짜 문항 번호가
"오탐지 의심"이 되고, 본문 한가운데·보기 오른쪽 같은 엉뚱한 위치가 문항으로** 잡혔다. 같은 PDF를 감지 코드만 바꿔 돌린 결과다.

| 코드 | 경계 | 오탐 | 같은 (쪽,번호) 중복 |
|---|---:|---:|---:|
| B18 이전 (`6862b75`) | 393 | 8 | 1 |
| 현재 main (B18 포함) | 840 | 378 | 249 |

이 PDF에는 보이는 번호(13~20pt) 옆에 **0.1pt짜리 보이지 않는 번호 글자**가 따로 들어 있다(HWP 출력의 텍스트 층으로 추정).
예: 28쪽 보이는 `27.`(x0=71, y=101) ↔ 보이지 않는 `27.`(x0=95, y=110). 보이지 않는 번호는 1·2·3…으로 빈틈없이 이어져
adaptive(순서 패턴) 감지의 최고 점수 그룹이 된다. 정규식 경로는 `size <= 1.0` 글자를 이미 버리지만 **adaptive 입력은 거르지 않는다.**
B18 이전에는 번호로 병합해 보이지 않는 쪽이 "번호 이미 있음"으로 버려졌다(우연히 정답). B18이 **위치로** 병합하면서 둘 다 남고,
adaptive가 확인하지 않은 보이는 진짜 번호가 "정규식 전용 경계"로 오탐 표시된다.

두 번째 문제는 B18이 한 쪽에 같은 번호의 경계 두 개를 허용하게 되면서 드러났다. 문항 식별자(ADR-0002 복합키 `{job_id}:{쪽}:{번호}`)와
문항 썸네일 캐시 키(`q_{쪽}_{번호}`)가 **겹친다.** dev 28쪽에서 오탐 "문항 27"과 진짜 "문항 27"이 같은 이미지로 보였다(스크린샷).
보이지 않는 글자를 고쳐도 `0929 테스트2`(내신마스터)의 "유형 01" 제목 ↔ "1." 문항 같은 **정당한 중복 5쌍**은 남는다.

세 번째 문제는 Phase 1 구현(`d4b5462`) 뒤 실측에서 드러났다. 보이지 않는 글자를 빼자 테스트02는 경계 840→378·오탐 378→106으로
줄었지만 **20pt `0N` 번호(기본문제) 106건이 여전히 오탐**이다(11쪽 `02` 포함). 이 PDF는 보이는 번호가 13pt `N.`(272건)과 20pt `0N`
두 형식이고, adaptive는 **최고 점수 한 그룹만** 인정해서 두 번째 형식 전체가 B18의 "정규식 전용 경계 = 오탐"에 걸린다.
B18 이전 대비 정상 경계 15개는 아예 사라졌다. 문제는 내신마스터의 "유형 01·02…" 소제목(B18이 오탐으로 잡으려던 62건)도 **형식이 일관된
두 번째 번호 그룹**이라는 점이다 — 두 번째 그룹을 인정하는 규칙은 그 62건을 다시 정상으로 되돌릴 수 있다(추정).
