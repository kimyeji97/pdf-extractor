# PLAN-B27 · 알림이 사용자 구분 없이 공유 + 알림별 읽음

> 출처: 2026-10-02 dev 전체 확인(사용자 요청 2건) 중 발견 · 작성: 2026-10-02 · 상태: 🟡 진행 (Phase 1·2 코드 완료 · dev 확인 남음)

## 배경

- 알림 API 3종(`GET /notifications` · `GET /notifications/stream` · `POST /notifications/read`)에 **인증이 없고**, 피드가 **전 사용자의 알림**(파일명·성공/실패)을 준다 — 비로그인도 받는다
- 읽음은 서버 전체에 커서 하나 — 한 사람이 벨을 열면 모두의 뱃지가 0이 된다
- 사용자 요청: 확인·미확인 알림 구분(확인 = 클릭했는가) · 뱃지 = 미확인 개수

B24가 "알림 피드 사용자 구분은 확인 안 함"으로 남긴 부분이다. 오픈(2026-10-06) 전 필수.

## 범위

**포함**
- 3종에 인증, `user`는 본인 알림만 · `admin`은 전체(B24와 같은 규칙)
- 알림별 읽음: 클릭한 알림만 읽음, 뱃지 = 미확인 개수, 팝오버에 '모두 읽음' 버튼
- 확인·미확인 알림 디자인 구분

**제외** — 알림 종류·문구 변경

- 기존 알림 테스트(F09·P04·P05·C09·B11)가 무인증으로 부른다 — `authed_client`로 옮긴다(계약 #30)
- 계약 #26 — 알림 GET·스트림은 `apiFetch`를 거치지 않는다(전역 딤). raw fetch에 `_authHeaders()`를 붙이고 B23-03 예외 목록(`listNotifications`·`markNotificationsRead`)에서 뺀다
- 계약 #27 — `unread_count`는 이제 단조 증가할 수 있지만 뱃지 가림 규칙(F09-47)과 충돌하지 않는지 본다
