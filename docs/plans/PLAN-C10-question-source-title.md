# PLAN-C10 · 감지 문항 이름을 원문으로 표시

> 출처: `docs/TODO.md` §8 · [PLAN-B20](PLAN-B20-invisible-number-and-id-collision.md) 범위 제외(2026-09-29 사용자 결정 "TODO로 분리") · 2026-10-01 세션 코드 확인·사용자 답변 · `/testrun` (c) 실측 후 개정(2026-10-01) · 작성: 2026-10-01 · 상태: ✅ 완료 (PR #27 main 머지 `b6edc0f` · dev 확인 2026-10-01)

## 배경

자동 감지 문항은 화면·PDF 어디서나 **"문항 {번호}"**로만 보인다. 감지가 번호 정수만 남기고 원문을 버리기 때문이다.
그래서 같은 쪽에 "유형 01" 제목과 "1." 문항이 함께 잡히면(B18 위치 병합 이후 정상 상태) 둘 다 "문항 1"로 보여
**어느 것이 어느 것인지 이름으로 구분할 수 없다**(2026-09-29 사용자 질문 "하나는 '유형1'인 것 같은데, 왜 문항1인건가?").
식별은 ADR-0006의 순번 k가 하고 있으므로 이 문제는 **표시 이름**의 문제다.

코드 확인(2026-10-01):
- `QuestionBoundary`에 원문 필드가 없다 — `number`(정수)와 사용자가 고친 `title`뿐이다
- 정규식 경로는 **단어 하나**를 매칭한다. "유형 01"은 두 단어로 들어와 "01"만 잡힌다(접두어 병합 `_PREFIX_KEYWORDS`에 "유형"이 없다)
- **"유형"은 번호와 같은 줄이 아니라 번호 바로 위에 얹혀 있다**(내신마스터 실측: `유형` 8pt top 105.0 x 85.3 / `01` 16pt top 114.6 x 84.0). 기출 4종·테스트02 전체에서 키워드가 번호 **바로 위**인 경계 63건(전부 내신마스터 "유형", 오탐 63건과 같은 수), **같은 줄 왼쪽** 0건
- adaptive 경로는 `_parse_candidate`가 (prefix, 번호, suffix)로 분해하지만 경계를 만들 때 번호만 넘긴다
- 프론트는 `title || (수동 ? "(수동 문항)" : "문항 N")` 폴백을 **화면마다 따로** 쓴다(작업 화면 목록·분석 패널·편집 화면 2곳·정렬 바스켓·미리보기 alt)
- PDF 라벨은 편집 화면의 `displayTitle` → `sel.label` → `pdf_service`로 흘러 **화면 이름이 곧 PDF 라벨**이다(계약 #12 단일 출처)

## 범위

**포함**
- 감지 결과에 원문을 남긴다 — 번호 토큰 + 키워드 접두어(같은 줄 왼쪽 또는 바로 위, 병합 뒤 한 곳에서, 두 경로의 경계 모두)
- 화면 표시 이름에 원문을 쓴다 — 사용자가 고친 이름이 있으면 그것이 우선
- 생성 PDF 라벨도 같은 이름 (계약 #12 단일 출처 유지)

**제외**
- **문항 식별자 변경** — 이름은 표시용이고 식별은 ADR-0006 복합키 그대로다(TODO §8 "식별자는 아니다")
- **기존 캐시 마이그레이션·일괄 재감지** — 원문이 없는 캐시는 재감지 전까지 "문항 N" 그대로(2026-10-01 사용자 결정)
- **"유제" 하위 문항 감지** — REQ-C11. 이 REQ는 이미 감지된 경계의 이름만 다룬다
- **저장된 문제집의 라벨** — `selections[].label`은 저장 당시 스냅샷이라 편집 복원 시 옛 "문항 N"이 그대로 보인다. 손대지 않는다(재선택하면 새 이름)

## 제약·함정

- **재감지는 사용자가 고친 제목을 지운다** — `_refresh_detection_body`가 경계 캐시를 지우고 새로 쓴다(`title` 병합 없음, 2026-10-01 코드 확인). 일괄 재감지를 기각한 이유이고, 원문을 `title`에 넣으면 이 문제가 더 드러난다
- **원문 수집은 감지와 같은 글자를 본다**(계약 #35) — 단어 필터(`size <= 1.0` 제외)가 다르면 HWP 출력 PDF의 숨은 0.1pt 번호가 원문으로 들어간다
- **원문 수집이 감지 결과를 바꾸면 안 된다**(계약 #11) — 접두어 목록을 감지의 `_PREFIX_KEYWORDS`와 공유하지 않는 이유다. "유형"이 단어 병합에 들어가면 "유형01" 가상 단어가 생겨 B18 "유형 N" 오탐 판정이 달라진다
- **감지 변경 실측에는 HWP 출력 PDF를 넣는다**(계약 #35) — 숨은 0.1pt 글자가 원문에 섞이지 않는지도 본다
- **새 필드는 기본값을 둔다** — `QuestionBoundary`는 옛 캐시를 `dataclass` 기본값으로 역직렬화한다. 기본값 없는 필드를 더하면 기존 캐시 전부가 로드에 실패한다
- **합성 PDF 무대는 실제 배치를 따라야 한다** — 첫 검증 계약(C10-01)이 "유형"을 같은 줄에 놓아 녹색이었지만 실제 PDF에선 0건이었다(2026-10-01 `/testrun` (c)). 배치 가정은 실측으로 확인한 뒤 케이스로 옮긴다
