# PLAN-C12 · 운영 콘솔 — 가입 승인 · 계정 차단 · 서버 수동 on/off

> 출처: 2026-10-08 세션 대화 · 작성: 2026-10-08 · 상태: 🟡 진행 (Phase 2/3)

## 배경

- 2026-10-06 오픈 뒤 누구나 가입하면 바로 쓴다. 가입자를 고를 수단이 없다.
- 문제 사용자를 막을 수단이 없다. 지금 계정 조작은 운영 콘솔의 admin 부여·회수뿐이다.
- prod 서버는 ECS 예약(평일 15:00 on · 23:00 off)으로만 켜지고 꺼진다. 예약 밖에 켜거나 일찍 끄려면 AWS 콘솔·CLI를 직접 만져야 한다.

## 범위

**포함**
- 가입 승인: 새 가입자는 승인 대기. 운영 콘솔에서 승인
- 계정 차단: 운영 콘솔에서 차단·해제
- 서버 수동 on/off: 운영 콘솔에서 ECS 서비스를 켜고 끈다

**제외**
- 승인·차단 알림 메일 — 메일 발송 수단이 없다
- 앱 안의 관리자 화면 — 운영 콘솔(내 맥 127.0.0.1, `scripts/ops/admin_console.py`)에서만 한다. prod API에 관리 엔드포인트를 새로 만들지 않는다(콘솔은 R2를 직접 읽고 쓴다 — 기존 관례)
- 별도 "거절" 상태 — 승인 대기에서 거절은 차단과 같다
- 예약 일시 중지·복구 — 수동 조작이 예약을 건너뛰게 하지 않는다(결정 참조)
- 차단 사용자의 데이터 삭제 — 데이터는 그대로 둔다

## 제약·함정

| 대상 | 내용 |
|---|---|
| 콘솔 저장소 접근 (계약 #24) | 콘솔은 저장소 설정을 **어떤 `app.*` 임포트보다 먼저** env로 넣는다 — 기존 구조 유지. 테스트 격리도 같은 이유 |
| 인증 통로 | 상태 검사는 **`_user_from_access_token` 한 곳 + `login` + `refresh`**. 쿠키 인증(`get_current_user_allow_cookie`, 계약 #31)도 같은 함수를 거치는지 확인할 것 — 빠지면 차단 사용자가 이미지·PDF는 계속 연다 |
| 기존 테스트 (계약 #30) | 인증 픽스처가 만드는 사용자에 `status`가 없으면 `active` 취급이라 기존 테스트는 안 깨져야 한다. 가입(`signup`) 테스트는 새 기본값 `pending`에 걸린다 |
| prod 예약 (CLAUDE 배포 상태) | `desired 0`은 장애가 아니다. 콘솔 on/off 외에 임의로 켜거나 끄지 않는다. 운영 구간 API(F19)는 예약을 읽으므로 수동 조작은 배너·다운 화면에 반영되지 않는다 |
