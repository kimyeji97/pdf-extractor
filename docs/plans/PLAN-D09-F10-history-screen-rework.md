# PLAN-D09 · PLAN-F10 — 생성 이력 화면 개편 + 이름 검색

> 출처: 2026-08-31 세션(TODO 3단계 착수) + 2026-07-29 번호 부여 시 원문 · 작성: 2026-08-31 · 상태: 📝 초안

## 배경

**생성 이력만 다른 은유를 쓴다.** 분석 목록은 전체 폭 카드 그리드 + 검색 바인데,
생성 이력은 진입하자마자 **420px 고정 목록 + 빈 미리보기 패널**로 갈라진 2패널이다.
결과는 두 가지다 — 목록은 좁은 칸에 갇혀 한 줄에 카드 2장만 들어가고,
**미리보기 자리는 아무것도 선택하지 않은 대부분의 시간 동안 빈 채로 화면 절반 이상을 차지한다.**

**검색이 없다.** 목록은 페이지네이션 + 무한 스크롤이라(REQ-P03-03) 문제집이 쌓이면
스크롤 말고는 특정 문제집에 닿을 방법이 없다. 분석 목록은 같은 문제를 이미 서버 검색으로 풀었다.

요구 원문(2026-07-29 `예정된작업.md`, 번호 부여 시점):

> **D09** — 진입 시 화면 UI는 문항 분석과 동일하게 가고, 클릭하면 현재 상태로.
> 클릭 시 애니메이션: 오른쪽에 미리보기 화면이 아코디언 액션으로 나타남 + 문제집 목록은 왼쪽 남은 영역으로 조율됨.
>
> **F10** — 문항 분석처럼 검색 기능.

## 범위

**포함**

- 진입 시 미리보기 패널을 걷어내고 **전체 폭 카드 그리드**로 (D09)
- 카드 클릭 → 우측 미리보기 아코디언 전개 + 목록이 남은 영역으로 축소 (D09)
- **문제집 이름 검색** — 서버 검색(`?name=`)에 디바운스로 연결 (F10)
- 앱 헤더 좌측 상단 **`문제집 검색` 입력란 제거** + 분석 화면의 `?q=` 흡수 로직 제거

**제외**

- **유형 검색** — 문제집 메타(`WorkbookSummary`)에 유형 필드 자체가 없다. 만들려면
  `extract-v2`가 소스 job의 `workbook_types`를 복사해 저장해야 하고 기존 문제집은 값이 비어
  검색에 안 걸린다(마이그레이션 판단이 따라온다). 2026-08-31 결정으로 **이름만** 한다.
- **레이아웃(2/4/6단) 필터** — 유형 대신 쓸 후보였으나 같은 결정에서 빠졌다. 요구에 없다.
- **통계 카드(StatCards)** — `/api/stats`는 전역 단일 지표(원본 수·총 문항수·문제집 수)라
  분석 화면과 **같은 숫자**가 두 화면에 뜬다. 2026-08-31 결정으로 붙이지 않는다.
- **메뉴 이름 변경**(생성 이력 → "결과") — TODO 신규 항목. 3단계 마지막에 다른 메뉴들과 함께.
- **벨 알림 클릭 시 문서 이름이 job-id로 뜨는 것** — TODO 신규 항목이고 분석 화면 쪽이다.
- **REQ-D10**(문항 목록 바둑판) — 다른 화면. 3단계에서 이 작업 뒤.
- **dev 배포** — 프론트 배포 정책(2026-08-28)상 로드맵 완료 시점에 모아서 올린다.

## 작업 단계

- [ ] **Phase 1** — 목록을 전체 폭 카드 그리드로. 진입 시 미리보기 패널을 렌더하지 않는다.
      완료 기준: 진입 직후 미리보기 패널이 **DOM에 없다**. 카드 그리드가 컨테이너 전체 폭을
      쓴다(한 줄에 들어가는 카드 수가 종전 2장에서 늘어난다). 카드를 클릭하기 전까지
      `GET /api/status/*` 호출 0건. 목록 내부 스크롤이 살아 있다(계약 #1).

- [ ] **Phase 2** — 클릭 시 우측 미리보기 아코디언 전개 + 목록 축소.
      완료 기준: 카드 클릭 → 미리보기 패널(기본 **720px 고정폭**)이 우측에 나타나고 목록이
      `flex:1`로 남은 영역을 갖는다. **같은 카드 재클릭 → 닫히고 목록이 전체 폭으로 복귀**
      (현행 토글 유지). 전환은 `theme.transitions.create(['width'])` **225ms**.
      `CardResizeHandle`(`dir: -1`)로 미리보기 폭을 조절할 수 있다.
      PDF 뷰어 내부 스크롤·확대가 종전과 같이 동작한다(계약 #2).
      미리보기 URL이 `toPreviewUrl`을 거친다(아래 함정).
      **폭 애니메이션 225ms 동안 PDF 뷰어가 매 프레임 재렌더되지 않는다** — CSS transition이라
      JS 리렌더가 붙지 않아야 하고, 붙으면 가상화 뷰어가 프레임마다 페이지를 다시 잰다.

- [ ] **Phase 3** — 이름 검색(F10).
      완료 기준: 검색어 입력 → 디바운스 300ms 뒤 `GET /api/workbooks?...&name=…`가 **1회**.
      검색어를 바꾸면 목록이 처음부터 다시 로드된다(`usePaginatedList`의 `fetchPage` 참조 교체).
      결과 0건이면 "검색 결과가 없습니다."가 뜬다(빈 목록 문구와 구분된다).
      **검색어가 바뀌면 열려 있던 미리보기가 닫힌다** — 닫는 시점은 목록이 실제로 교체되는
      시점, 즉 **디바운스된 값** 기준이다(원본 입력 기준으로 하면 목록은 그대로인데 미리보기만
      먼저 사라져 "같은 집합을 가리킨다"는 결정 근거가 깨진다).
      **`git diff backend/`가 비어 있다** — 백엔드 변경 0건이 이 Phase의 판정 중 하나다.

- [ ] **Phase 4** — 헤더 전역 검색 제거.
      완료 기준: `grep -rn '문제집 검색' frontend/src`가 **0건**. `/?q=테스트`로 직접 진입해도
      분석 화면 검색란이 비어 있다 — 흡수 로직이 사라졌으므로 **파라미터를 무시한다.**
      기존 테스트 회귀 0건.
      ⚠️ **주소창은 정리하지 않는다.** 종전 기준에 "`?q=`가 남지 않는다"가 함께 적혀 있었으나
      URL을 지우던 주체가 바로 그 흡수 로직(`setSearchParams({}, { replace: true })`)이라
      **두 조건을 동시에 만족하는 구현이 없다.** 헤더 검색이 사라지면 `/?q=`로 보내는 주체도
      없어지므로(손으로 친 경우만 남는다) 무시하는 쪽으로 정리했다. (2026-08-31, `/testgen`에서 발견)

- [ ] **Phase 5** — 육안 검증(로컬 프론트 + dev 백엔드).
      완료 기준: dev 백엔드 `desired 0→1` 후 `VITE_API_BASE_URL`을 dev로 주고 `npm run dev`.
      ① 진입 시 전체 폭 그리드 ② 카드 클릭 시 225ms 전개 + 목록 재배치 ③ 핸들로 폭 조절
      ④ 이름 검색이 뒷페이지 항목까지 찾는다(무한 스크롤로만 닿던 것) ⑤ 미리보기 PDF가
      **CORS 에러 없이** 뜬다 ⑥ 헤더에 검색란이 없다. **확인 후 `desired 0`으로 되돌린다.**

## 제약·함정

- **미리보기 URL은 반드시 `toPreviewUrl(download_url)`을 거친다.** 이 화면을 다시 쓰면서
  이 한 줄을 놓치면 2026-08-27 dev 사고가 그대로 재발한다 — 다운로드(`<a href>`, `Origin` 없음)가
  먼저 edge 캐시를 채우면 CORS 헤더 없는 사본이 남고, 버킷 CORS를 고쳐도 **캐시된 사본은 그대로라
  미리보기가 통째로 깨진다**(퍼지 권한이 없어 만료를 기다려야 했다). 다운로드 쪽에는 붙이지 않는다.
  presigned URL이면 쿼리가 서명 대상이라 403이 되므로 `toPreviewUrl`이 이미 걸러 준다.
- **계약 #1 높이 체인** — `WorkCanvas`/`CardRow`/`PanelCard` 조합을 유지한다. 목록을 전체 폭으로
  바꾸며 래퍼를 손대는 작업이라 `flex:1`/`minHeight:0`/`overflow:hidden`이 빠지기 쉽다.
  한 군데만 빠져도 내부 스크롤이 죽는다(REQ-B04·B05·B08의 공통 원인).
- **계약 #2** — `PdfPreviewPanel`은 소비처가 flex 컬럼 부모(`minHeight:0`)를 줘야 한다.
  아코디언으로 감싸면서 래퍼가 한 겹 늘어나는 자리다.
- **계약 #19** — `CardRow`에 `gap`을 걸지 않는다. 카드 사이 여백은 현재 `width:16` Box가 만든다.
  둘 다 걸면 간격이 두 배가 된다.
- **계약 #5** — 목록 폭이 **동적**이 되므로 카드 `flexShrink:0`를 확인한다. 축소되면 카드의
  `overflow:hidden`이 표지 이미지를 잘라내는데, **목록이 스크롤되지 않아 "이미지가 좀 짧다"로만 보인다.**
- **계약 #17** — 색 해시·식별 키는 `workbook_id`다(`colorKey={wb.workbook_id}`). `name`은 고유하지
  않다(실데이터에 같은 이름 2건). 이름으로 바꾸면 서로 다른 문제집이 같은 색이 된다.
- **계약 #15** — 표지 썸네일 URL은 결정적으로 조립한다. URL을 얻으려고 목록 API를 더 부르지 않는다.
- 검색 요청은 `apiFetch` 경유라 디바운스마다 전역 딤이 켜진다. **분석 화면이 이미 같다** —
  사용자가 시킨 요청이므로 계약 #26 위반이 아니다. 새로 raw `fetch`로 바꾸지 말 것.
- 현재 이 화면·헤더를 덮는 테스트는 없다(테스트 16파일 전부 알림 경로·유틸). **무대 붕괴 예고는 없지만
  회귀를 잡아 줄 그물도 없다**는 뜻이다 — `/testgen`에서 케이스를 새로 만든다.
- **`PANEL_BOUNDS`는 `work.jsx` 값을 그대로 쓰지 않는다.** 거기 `section3`은 문항 목록이라
  `[200, 800]`인데 이쪽은 PDF 지면이다. **잠정 `[480, 1000]` · 기본 720으로 두고 Phase 5 육안에서
  조정한다** — 지금 정한 값은 계산이 아니라 출발점이다. 상수는 **모듈 스코프**에 둔다
  (`work.jsx` 주석대로, 컴포넌트 안에 두면 `[]` 의존성 이펙트가 첫 렌더 객체를 붙든다).
- **dev 백엔드를 켜면 첫 연결이 ~31초 걸릴 수 있다.** `desired 0→1` 직후 `EventSource.onopen`이
  두 번 ~31s였던 것이 C09에서 관측됐고 P05에서는 재현되지 않았다(원인 불명). 육안 검증 중
  화면이 안 뜬다고 이번 변경을 의심하기 전에 **콜드 구간인지부터 본다.**
- **육안 검증은 dev 실데이터 위에서 한다** — 이 화면에는 **삭제 버튼이 있다**(문제집 + 결과 PDF,
  되돌릴 수 없음). 카드 액션을 훑을 때 누르지 않도록 주의한다.
