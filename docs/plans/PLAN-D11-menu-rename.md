# PLAN-D11 · 메뉴 이름 변경 (분석 / 생성 / 결과 / 템플릿 관리) + 경로 변경

> 출처: 2026-08-28 `docs/TODO.md` 신규 항목 ① 원문 + 2026-09-03 신규 항목 묶음 대화 + 2026-09-03 미결 정리 · 작성: 2026-09-03 · 상태: 🟡 진행 — Phase 1 완료 2026-09-04, Phase 2 미착수 (미결 0건)

## 배경

**메뉴 이름이 화면의 역할이 아니라 기능의 동작을 말한다.** 사이드바 4개가 "문항 분석 · 문제집 편집 ·
생성 이력 · 표지 관리"인데, 사용자가 원하는 이름은 흐름의 단계 — **분석 → 생성 → 결과**, 그리고
재료를 두는 곳 **템플릿 관리**다. "문제집 편집"은 실제로 하는 일이 문제집을 **만드는** 것이라
이름이 어긋나고, "생성 이력"은 결과물을 받아 가는 곳인데 "이력"이라 부차적으로 읽힌다.

요구 원문(2026-08-28 `docs/TODO.md` 신규 항목 ①):

> 메뉴 이름 변경
> - 분석 (as-is 문항 분석)
> - 생성 (as-is: 문제집 생성)
> - 결과 (as-is: 생성 이력)
> - 템플릿 관리 (현재는 표지만) (as-is: 표지 관리?)
>
> (아래는 as-is, to-be 메뉴 이름 섞여 있음.)

원문의 as-is 표기 하나가 실제와 다르다 — "문제집 생성"이라 적혔지만 **현재 메뉴는 "문제집 편집"**이다
(`nav-config.tsx`). to-be "생성"이 가리키는 화면은 `/editor`(문제집 편집)가 맞다.

**이름이 박힌 자리는 셋이다**(2026-09-03 전수 확인): ① 사이드바 `nav-config.tsx` 제목 4개,
② 각 화면 `PageHeader`의 `title`과 브레드크럼(분석 목록·작업 화면·편집·이력·표지 5곳),
③ **옛 메뉴명을 가리키는 안내 문구** — 이력 빈 상태 "문제집 편집 탭에서 PDF를 생성하면",
분석 삭제 확인 "생성 이력은 남지만, 편집 화면에서…". 메뉴만 바꾸고 ③을 두면 안내가 없는 메뉴를 가리킨다.

**경로도 옛 이름을 따른다** — `/editor`·`/history`·`/format`. 2026-09-03 미결 정리에서 **이번에 함께
바꾸기로** 했다(아래 결정). 경로 문자열은 `paths.ts` 말고도 **`NotificationBell`의 이동 대상(`/history`)과
편집 화면 브레드크럼(`to: "/editor"`)이 직접 들고 있다** — 한 곳만 바꾸면 벨 클릭이 빈 화면으로 간다.

## 범위

**포함**

- 사이드바 메뉴 제목 4개: 문항 분석 → **분석**, 문제집 편집 → **생성**, 생성 이력 → **결과**,
  표지 관리 → **템플릿 관리**
- 라우트 경로 3개: `/editor` → **`/create`**, `/history` → **`/results`**, `/format` → **`/templates`**
  (분석은 `/`·`/analysis/:jobId` 그대로). 경로 문자열을 직접 든 곳(벨 이동 대상·브레드크럼 `to`)도 함께
- 각 화면 `PageHeader` 제목·브레드크럼을 메뉴명과 일치시킴
- 안내 문구 2곳을 아래 문장으로(결정 표):
  - 결과 빈 상태: "문제집 편집 탭에서 PDF를 생성하면 여기에 기록됩니다." →
    **"생성 메뉴에서 PDF를 만들면 여기에 기록됩니다."**
  - 분석 삭제 확인: "이 문제집의 문항으로 만든 생성 이력은 남지만, 편집 화면에서 해당 문항 이미지가
    보이지 않습니다." →
    **"이 문제집의 문항으로 만든 결과는 남지만, 생성 화면에서 해당 문항 이미지가 보이지 않습니다."**

**제외**

- **옛 경로 리다이렉트** — 2026-09-03 결정: 두지 않는다. 옛 URL·북마크는 깨진다(dev 프론트는 로드맵
  끝에 재배포되므로 실제 노출은 그때). 라우트 3개가 늘어나는 비용을 안 치른다.
- **표지 설명 문구** "문제집 생성 시 첫 페이지로 넣을 표지를 관리합니다." — 메뉴명이 아니라 시점을 말한다.
  그대로 둔다.
- **서버 알림 제목**("문항 감지 완료"·"문제집 생성 완료") — 메뉴명이 아니라 사건 이름이고 백엔드
  `notification_service`가 만든다. 프론트 테스트 6곳이 이 문자열을 고정하고 있다.
- **브라우저 탭 제목** `PDF 문항 추출기`(`index.html`) — 메뉴가 아니다.
- **코드 주석·테스트 설명문에 든 옛 이름** — 화면에 안 보인다. 바꾸면 diff만 커진다.
- **REQ-30 템플릿 엔티티** — 이 작업은 이름·경로만 바꾼다. "템플릿 관리" 화면의 기능은 표지 CRUD 그대로.
- **dev 프론트 배포** — 프론트 배포 정책(2026-08-28)상 로드맵 3단계 완료 시점에 모아서.

## 제약·함정

- **경로 문자열을 네 곳이 각자 든다** — `paths.ts`, `NotificationBell`의 `destinationOf`(`/history` 직접),
  편집 화면 브레드크럼(`to: "/editor"` 직접), F11 가드의 목록 이동(`/`, 이번엔 안 바뀜). 벨만 안 고치면
  "문제집 생성 완료" 클릭이 **404가 아니라 빈 화면**으로 간다(라우터 폴백 없음). Phase 2 완료 기준에
  벨 이동을 넣은 이유다. 구현은 직접 문자열을 `paths`로 바꾸는 쪽이 맞다 — 그래야 다음 변경에서
  같은 함정이 안 생긴다.
- **nav 활성 판정은 경로 접두로 한다**(`nav.tsx` — "문항 분석은 '/'이자 '/analysis/:jobId'의 상위").
  `/`가 모든 경로의 접두라 분석이 항상 활성이 되지 않도록 이미 예외 처리가 있다 — 새 경로가 이
  예외를 건드리지 않는지 Phase 2에서 확인.
- **테스트가 경로·문자열을 잡는 곳** — `history/index.test.jsx`(12건)가 `MemoryRouter` 초기 경로를
  옛 경로로 잡고 있으면 Phase 2에서 깨진다. 그건 (a) 테스트 결함이다 — 구현이 아니라 테스트를
  고친다(`/testrun`). `[F11-04] … 문항 분석 목록으로 이동한다`는 테스트명일 뿐 단언은 `/`라 안 깨진다.
- **문자열 전수 확인은 `grep`으로 하되 주석을 걸러야 한다** — 옛 이름이 주석·훅 설명에 10곳 넘게
  남아 있다. "0건"의 기준은 **렌더되는 문자열**이다.
- **dev 프론트의 옛 URL은 재배포 시점에 깨진다** — 리다이렉트를 안 두기로 했으므로, 재배포 뒤
  "북마크가 안 열린다"는 버그가 아니라 결정이다. PROGRESS에 그때 한 줄 남길 것.
- 계약 #25 — 테스트명에 `[D11-NN]`, 컴포넌트는 `ThemeProvider` 아래에서. nav는 라우터도 필요하다
  (`MemoryRouter`, D09 무대와 같다).
