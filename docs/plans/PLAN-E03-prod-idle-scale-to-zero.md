# PLAN-E03 · prod 유휴 시 0으로 내리고 접속하면 깨운다

> 출처: 2026-11-02 세션 대화 · 작성: 2026-11-02 · 상태: 🟡 진행

## 배경

prod가 아무도 안 쓰는 시간에도 2 vCPU / 4GB로 떠 있다.

| 항목 | 10월 실측 |
|---|---|
| AWS 청구 | $36.6 (49,484원) |
| prod Fargate | 약 135시간, 약 $15.3 |
| prod CPU | 일 평균 0.1~0.2%, 일 최대 5~9% |
| prod 메모리 | 약 3% (약 120MB / 4GB) |

- 지금은 ECS 예약 작업이 평일 15:00~23:00에 켜 둔다(REQ-F19). 그 8시간 동안 요청이 없어도 돈이 나간다.
- 사양을 줄이는 것만으로는 이 낭비가 남는다. 쓰는 시간에만 떠 있어야 한다.

## 범위

**포함**
- 백엔드가 일정 시간 요청이 없으면 스스로 prod 서비스를 `desired 0`으로 내린다
- 백엔드가 꺼진 동안 사용자가 서버를 깨울 수 있는 경로(웨이커)
- F19 다운 안내 화면에 깨우기 버튼과 기동 대기 표시
- prod 적용과 예약 작업(`on`/`off`) 정리

**제외**
- 스케일아웃(태스크 2개 이상)과 prod 사양 축소(2 vCPU → 1 vCPU). 이번 Phase 1 실측을 보고 다시 정한다(2026-11-02 사용자 결정)
  - 하려는 이유: 태스크를 작게 줄이고 필요할 때 필요한 만큼만 늘려 비용을 줄인다
  - 2026-11-02 분석: 계약 #43 외에 SSE 브로커·공유 캐시·`_dir_cache`·기동 시 `fail_interrupted()`가 프로세스 1개 전제다. REQ 1개, Phase 4~5개 규모로 추정
- 롤링 배포 중 태스크가 겹쳐 진행 중 분석이 FAILED가 되는 것. 사용자가 실패를 보고 재감지하면 된다(2026-11-02 사용자 결정, 감수)
- PDF 생성 중 태스크가 죽어 `PROCESSING`에 멈추는 것. `docs/TODO.md`로 넘겼다(2026-11-02)
- dev 절감. 2026-11-02에 이미 적용했다(매일 00:00 강제 off + Fargate Spot, CLAUDE.md 배포 상태)

| 대상 | 내용 |
|---|---|
| 스케일인 시점 | 감지·PDF 생성이 백그라운드로 도는 중에 끄면 작업이 고아가 된다(`PROCESSING`에 멈춤). 진행 중 작업이 있으면 끄지 않는다 |

| 단일 프로세스 | 유휴 시계와 진행 중 작업 판정은 프로세스 메모리로 충분하다. 계약 #43과 같은 전제라 스케일아웃 때 함께 바꿔야 한다 |

| 웨이커 응답 | 웨이커는 `apiFetch`를 거치지 않는다. 거치면 `GlobalDim`이 켜지고 실패 시 다운 감지가 또 돈다(계약 #26). `client.js`에 두면 B23-03 가드 대상이다(계약 #31) |
