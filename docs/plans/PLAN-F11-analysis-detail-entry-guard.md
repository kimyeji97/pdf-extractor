# PLAN-F11 · 재감지 중 문항 분석 상세 진입 차단

> 출처: 2026-08-10 세션 (REQ-F09 육안 검증 중 발견) · 작성: 2026-08-10 ·
> 상태: ✅ **완료 (2026-08-10) — 케이스 10/10 + 육안 확인** · **미배포** · 미결 2건 남음

## 배경

문항 분석 상세(작업 화면)는 **감지가 도는 중에도 열린다.** 목록 카드의 `isAnalyzing()`이
클릭만 막을 뿐이라 **URL 직접 입력과 뒤로가기로는 그대로 들어가진다.**

들어가면 문항이 아직 없거나 이전 감지 결과가 남은 화면을 보게 되고, 그 상태에서 '재감지'를
한 번 더 누를 수 있다. **F09가 만든 구멍이 아니다** — 목록 쪽 차단이 처음 들어올 때부터
클릭 경로만 막고 있었고, F09 육안 검증 중에 눈에 띈 것뿐이다.

## 범위

**포함**

- 감지 중(`PROCESSING`) 진입 차단 — 확인 버튼 있는 모달 → 문항 분석 목록으로 이동
- 대기 중(`PENDING`) — 진입은 허용하되 **'재감지' 버튼만 비활성 + "재감지 대기 중" 표시**
- **목록의 `isAnalyzing()`을 같은 규칙으로 맞춤** — `PROCESSING`만 클릭 차단(2026-08-10 확정)

**제외**

- **완료 후 자동 재진입** — 나간 뒤 그 파일의 감지가 끝나도 자동으로 다시 들여보내지 않는다.
  사용자가 목록에서 다시 클릭한다(2026-08-10 확정). 의도치 않은 화면 이동을 만들지 않는다는
  점에서 B10의 자동 다운로드 결정과 같은 계열이다.
- **감지 중 화면에 머무는 경우** — 상세에서 직접 '재감지'를 눌러 `PROCESSING`이 된 사용자는
  **쫓아내지 않는다.** 요구가 "진입 시"에 걸려 있고, 자기가 시작한 작업에서 튕겨나가는 것은
  기능이 아니라 버그로 읽힌다.
- **편집·생성 이력 등 다른 화면** — 같은 구멍이 있는지 확인하지 않았다. 이번 범위 밖.

## 제약·함정

- **상태 조회를 새로 추가하지 않는다**(계약 #15 계열). 작업 화면은 원본 PDF URL 때문에
  `getJobInfo`를 이미 부르고 있고, 그 응답에 `boundaries_status`가 들어 있다.
  URL·상태를 얻자고 목록 API나 전용 엔드포인트를 덧붙이는 것이 REQ-P02-02에서 걷어낸 낭비다.
- **감지 완료를 폴링으로 기다리지 않는다**(계약 #27). "재감지 대기 중" 표시를 살아 있게
  만들려고 `setInterval`을 되살리면 **REQ-F09 Phase 3이 걷어낸 것을 그대로 복원**하는 셈이다.
  화면이 완료를 알아야 하면 `useJobCompletion`을 쓴다.
- **모달 색조는 `theme/tint.js`**(계약 #20). 라이트/다크가 팔레트를 공유하므로 밝기 변형
  토큰을 쓰면 다크에서 깨지고, 콘솔·빌드는 조용하다.
- **모달 문구가 상태를 오해하게 만들면 안 된다.** 감지 중과 **조회 실패**는 같은 경로로 막히지만
  원인이 다르다 — 실패에 "재감지 중입니다"라고 쓰면 **없는 사실을 알리는 것**이고, 사용자는
  기다리면 끝난다고 믿는다. 두 경우를 구분해 말해야 한다.
- **뒤로가기로 되돌아오는 경로를 잊지 말 것.** 목록으로 내보낸 뒤 사용자가 뒤로가기를 누르면
  다시 상세로 들어온다 — 가드가 마운트마다 도는지(그래서 다시 모달이 뜨는지) 확인해야 한다.
  이 구멍이 애초에 뒤로가기로 열렸다는 점에서 같은 자리다.
