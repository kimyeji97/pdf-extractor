# PLAN-F14 · 문항분석 현황판 개선 + 시스템 전체 뱃지 색상 정리

> 출처: `docs/TODO.md` §8(2026-09-29 dev 육안 5건 + 2026-09-30 사용자 추가 1건) + 2026-09-30 세션 코드 확인 · 작성: 2026-09-30 · 상태: ✅ 완료 (PR #26 main 머지 `f18c495` · dev 확인 2026-09-30)

## 배경

문항분석 목록 화면(`pages/analysis/index.jsx`)의 현황판(`components/StatCards.jsx` — `StatsBoard`)과 상태 뱃지가 서로 다른 말을 한다.

1. **업로드 직후 목록 뱃지는 "대기 중", 현황판은 "분석 중"에 1** — 새로고침하면 뱃지도 "분석 중"이 된다(사용자 육안).
   코드 확인: 업로드 백그라운드 작업이 `QUEUED`로 쓰고 슬롯을 잡자마자 `PROCESSING`으로 쓴다(`upload.py`). 업로드 뒤 목록과 현황판을
   각각 한 번 받는데 받는 시점이 달라 한쪽은 `QUEUED`, 한쪽은 `PROCESSING`을 본다. 그 뒤엔 **감지 시작을 알리는 이벤트가 없어**
   완료 알림 전까지 목록이 `QUEUED`에 머문다
2. **분석 완료 알림(SSE)을 받아도 현황판 숫자가 그대로** — 코드 확인: `useNotificationRefresh`(계약 #27)가 목록(`fetchJobs`)만 다시 읽는다.
   현황판은 업로드·삭제·편집 때(`bumpStats`)만 다시 읽는다
3. **현황판 색과 뱃지 색이 다르다.** 같은 상태가 곳마다 다른 색·다른 이름이다(2026-09-30 확인):

   | 상태 | 현황판 타일 | 목록 카드 뱃지(`analysis/index.jsx`) | 편집 화면 파일 목록(`FileListPanel`) |
   |---|---|---|---|
   | PROCESSING | "분석중 파일수" · info | "분석 중" · warning | "감지 중…" · warning |
   | QUEUED | "대기 중 파일수" · primary | "대기 중" · info | "대기 중" · info |
   | PENDING | — | "처리 중" · warning | "감지 대기" · default |
   | FAILED | — | "분석 실패" · error | "감지 실패" · error |
   | 오탐 | "오탐 문항 수" · error | — | — (작업 화면 "오탐 N"·분석 패널 "오탐지 의심" · warning) |
   | 수동 | "수동 문항 수" · secondary | — | — (분석 패널 "수동" · info, 문항 목록 "수동" · primary) |

4. **시스템 전체 뱃지 색 정리**(2026-09-30 사용자 추가) — 위 표처럼 현황판만의 문제가 아니다. 앱 전역의 상태 뱃지 색 규칙을 하나로
5. **현황판 상세 영역을 닫을 수 없다**(사용자 육안). 코드상으로는 같은 타일을 다시 누르면 닫히지만(`handleTileClick` 토글) 닫기 수단이 보이지 않는다
6. **상세 영역 위치** — 지금은 현황판 안 우측(폭 320)에 붙는다. 하단 문제집 목록 영역의 우측으로 옮긴다(검색란까지 목록 영역으로 본다, 사용자 요청)
