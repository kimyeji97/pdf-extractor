# PLAN-F16 · 생성된 PDF 저장 — 브라우저 저장 위치 선택 창

> 출처: 2026-10-02 dev 전체 확인(사용자) · 작성: 2026-10-02 · 상태: 📝 초안 (같은 날 "새 탭 열기" → "저장 위치 선택"으로 바뀜)

## 배경

PDF 생성이 끝나면 지금은 자동 다운로드(기본 폴더)만 한다. 저장 위치를 고르고 싶다.

## 범위

**포함** — 생성 완료 후 [다운로드] 버튼 → 브라우저 **기본 저장 위치 선택 창**(우리가 모달을 만들지 않음) → 저장하면 끝

**제외**
- 브라우저 새 탭으로 열기 · 완료 시 자동 열기 — "자동으로 브라우저에 열리는 건 제공하지 말자"(2026-10-02 사용자)
- 완료 시 자동 다운로드 — 버튼으로만 저장(같은 결정)
- 자체 경로 선택 모달

## 결정

| 항목 | 결정 | 근거 | 기각한 안 |
|------|------|------|-----------|
| 저장 방식 | 버튼 클릭 → `window.showSaveFilePicker`(File System Access API)로 위치 선택 → PDF를 받아 그 파일에 쓴다 | 브라우저 기본 창 — 2026-10-02 사용자 결정 | 자체 모달 · 새 탭 열기(첫 결정, 같은 날 교체) |
| 지원 안 하는 브라우저 | Safari·Firefox는 API가 없다 → 지금처럼 `<a download>`(브라우저 설정의 "저장 위치 묻기"를 따른다) | 표준 API가 Chromium 계열뿐 | 그 브라우저에선 버튼 숨기기 |

## 작업 단계

- [ ] **Phase 1** — 자동 다운로드 제거 + [다운로드] 버튼(위치 선택 창, 미지원 시 일반 다운로드)
      완료 기준: dev Chrome에서 위치 선택 창이 뜨고 고른 곳에 PDF가 저장됨 · 완료 시 아무것도 자동으로 열리거나 받아지지 않음

## 제약·함정

- 선택 창은 **사용자 클릭 안에서** 열어야 한다(비동기 대기 뒤 열면 거부) — 창부터 띄우고 그 뒤 PDF를 받는다
- PDF를 `fetch`로 받으므로 R2 공개 도메인의 **CORS**에 dev 오리진이 있어야 한다(버킷 설정, CLAUDE.md 배포 상태 참고)
- 사용자가 창을 취소하면(`AbortError`) 조용히 끝낸다
- 계약 #22 — 완료 시 부수효과는 `useJobCompletion` 콜백 안
