# PLAN-F17 · 출처 문구 형식 "n번) 문제집. p쪽. 문항이름."

> 출처: 2026-10-02 dev 전체 확인(사용자) · 작성: 2026-10-02 · 상태: 📝 초안

## 배경

생성 PDF·미리보기의 문항 출처가 지금 "n번. 문제집이름. p3. 문항이름"이고, 업로드 때 문제집 이름을 안 넣은 파일은 이름이 빠진다.

> 현재 구현(2026-10-03 확인): 프론트·백엔드 둘 다 `["n번", 문제집, "p{page_num+1}", 문항이름]`을 `". "`로 join하고
> **값이 없는 요소는 생략**한다. 그래서 이름 없는 파일은 칸이 비는 게 아니라 **아예 빠져** `1번. p3. …`이 된다.
> 쪽 번호는 이미 1-based다(`page_num + 1`).

## 범위

**포함** — 형식 "**n번) 문제집. p쪽. 문항이름.**" · 이름 없으면 파일명(확장자 제외) · **분석 목록 등 이름 표시에서도 확장자를 뺀다**
· **제목·부제(`resolveDocumentName`·`resolveFileSubtitle`, F15/B12) 규칙과 생성 코드 통일** — 2026-10-03에 범위로 들어왔다.
F17의 이름 규칙이 제목·부제 중복 판정을 바꾸고, 제목 생성 코드가 두 벌이라 한쪽만 고치면 갈리기 때문

**제외** — 라벨 위치·글꼴 · **결과(생성 이력) 화면**(원본 파일명을 그리는 자리가 없다 — 그리는 건 생성된 문제집의 이름이다)

## 제약·함정

- `resolveFileSubtitle`(F15)은 "이름 = 파일명에서 확장자 뺀 것"이면 파일명을 숨긴다 — 이름 규칙을 바꿀 때 같이 본다
  ⚠️ **F17이 이 REQ의 범위를 F15/B12 코드까지 넓힌다**(2026-10-03 결정). 판정 기준을 "**둘 다 확장자를 뺀 뒤 비교**"로 바꾼다 — 지금은 `!name`이면 즉시 `null`이라 **이름 없는 파일이 그 가지에서 먼저 끊긴다**.
  ⚠️ **제목을 만드는 코드가 두 벌이고 폴백이 다르다** — 작업 화면은 `resolveDocumentName(jobInfo, jobId)`(최후 `jobId`), 목록 카드는 **인라인** `job.workbook_name || job.filename || "unknown.pdf"`. 한 벌로 합칠 때 **폴백이 조용히 바뀐다**.
  ⚠️ 부제는 `BookCard`의 `caption`이다 — 같은 카드의 `subtitle` prop은 **업로드 상대 시각**("3일 전")이라 다른 줄이다. 이름이 겹치니 코드에서 헷갈리지 말 것.
- 계약 #12 — 라벨은 `WorkbookPreview`와 `pdf_service`가 같은 문자열을 그린다. 한쪽만 고치면 미리보기와 PDF가 갈린다
