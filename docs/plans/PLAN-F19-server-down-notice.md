# PLAN-F19 · 백엔드가 꺼져 있거나 꺼질 예정이면 사용자에게 알린다

> 출처: 2026-10-07 세션 대화 · 작성: 2026-10-07 · 상태: 🟡 진행 (Phase 1/4)

## 배경

**백엔드가 꺼져 있으면 화면이 무엇이 잘못됐는지 말해 주지 않는다.**
꺼진 동안 들어온 사용자는 다음 중 하나를 본다.
- 빈 목록
- 화면마다 제각각인 에러 문구
- 로그인 실패

꺼진 백엔드는 HTTP 상태 코드로 오지 않는다. **`fetch`가 `TypeError: Failed to fetch`로 reject한다.**
Cloudflare Tunnel이 530·502를 줘도 CORS 헤더가 없어 브라우저에는 같은 네트워크 에러로 보인다(계약 #8).

**꺼지기 직전에 쓰던 사용자는 예고 없이 끊긴다.**
prod는 ECS Auto Scaling 예약 작업으로 켜지고 꺼진다(2026-10-07 실측).

| 예약 작업 | cron | 시간대 |
|---|---|---|
| `on` | `cron(0 15 ? * MON-FRI *)` | Asia/Seoul |
| `off` | `cron(0 23 ? * MON-FRI *)` | Asia/Seoul |

꺼지는 시각은 사용자가 수시로 바꾼다.

## 범위

**포함**
- **서버 다운 감지** — `apiFetch` 경로(`_rawFetch`)에서 네트워크 reject를 잡아 **별도 경로로 이동**한다
- **다운 안내 화면** — 재시도 버튼이 `/health`로 복구를 확인하면 원래 경로로 돌아간다. 오프라인과 서버 다운을 구분할 수 있으면 구분한다
- **최상위 `errorElement`** — 렌더 크래시나 청크 로드 실패로 흰 화면이 뜨는 것을 막는다
- **꺼짐 예고 배너** — 꺼지기 1시간 전부터 화면 상단 한쪽에 상시 표시한다. 내용은 남은 시간 카운트다운과 진행 중 작업이 끊긴다는 경고다. 로그인·회원가입 화면에도 띄운다
- **운영 구간 API** — 백엔드가 AWS 예약 작업에서 앞으로 2주 치 운영 구간을 계산해 준다. 무인증이다
- **다운 안내 화면의 운영 시간 표기** — "다음 운영: 10월 8일(목) 15:00 ~ 23:00"

**제외**
- **배경 경로의 실패는 감지하지 않는다** — 계약 #26의 raw fetch(`getStatus`·`listNotifications`·`{background:true}`)와 SSE 재연결. 일시적으로 끊길 때마다 이동하면 화면이 튄다
- **CORS 헤더가 붙은 5xx(502·503·504)** — 2026-10-07 사용자 결정 "미포함". "꺼짐"과 "느림"을 섞지 않는다
- **자동 복구 폴링** — 2026-10-07 사용자 결정 "버튼". 사용자가 재시도를 직접 누른다
- **화면별 `catch`·에러 문구 정리** — 기존 처리는 그대로 둔다
- **꺼지는 순간 진행 중이던 작업(감지·PDF 생성)을 보호하는 것** — 이번에는 알리기만 한다

## 제약·함정

| 대상 | 내용 |
|---|---|
| `/health` 경로 | `/api` 아래가 아니다(`main.py`의 `@app.get("/health")`). `BASE_URL`(`…/api`)에 이어 붙이면 404가 난다 |
| 재시도·꺼짐 예정 조회 | `apiFetch`를 거치지 않는다. 거치면 `GlobalDim`이 켜지고, 재시도가 실패하면 감지가 또 일어난다(계약 #26) |
| 계약 #31 가드 | 운영 구간 조회는 무인증 raw fetch다. B23-03 무인증 예외 목록에 이유(로그인 화면 배너)와 함께 올린다. 빠뜨리면 B23-03이 실패한다 |
| `_inflightGets` | 같은 URL의 GET이 한 reject를 함께 받는다. 이동이 한 번만 일어나야 한다 |
| 운영 구간 저장 | 브라우저 저장소 읽기·쓰기는 try/catch로 감싼다. 비공개 창 등에서 막혀도 다운 화면은 뜨고, 운영 시간 줄만 빠진다 |
| 다운 안내 경로 | `RequireAuth` 밖에 둔다. 안에 두면 미인증 사용자가 `/login`으로 튕긴다 |
| AWS cron 형식 | 6필드에 `?`와 연도 필드가 있어 일반 cron(5필드)과 다르다. `Timezone` 필드를 따로 준다. `at(...)` 일회성 표현식도 올 수 있다. 꺼짐 예약 작업은 `MaxCapacity: 0`으로 식별한다. 이름 `off`에 의존하지 않는다 |
| 응답 시각 | 백엔드는 운영 구간을 **절대 시각(ISO, 시간대 포함)** 으로 준다. 프론트가 cron을 해석하지 않는다. `on` 예약 작업은 `MinCapacity ≥ 1`로 식별한다 |
| 조회 실패 | AWS 조회가 실패해도 앱 동작에 영향을 주지 않는다. 배너만 안 뜬다 |
| 백엔드 테스트 | 스토리지 격리(계약 #24)와 같은 이유로 실제 AWS를 부르지 않는다. 클라이언트를 mock한다 |
| 프론트 테스트 | 앱과 같은 `ThemeProvider` 아래에서 렌더한다. 타이머를 스파이하는 케이스에서는 `waitFor`를 쓰지 않는다(계약 #25) |
| 배너 색 | `tintBg`나 모드별 토큰으로 칠한다. `*.lighter`는 다크 모드에서 깨진다(계약 #20) |
| 육안 확인 | 로컬 uvicorn을 끄는 것으로 한다. dev·prod 백엔드를 켜고 끄는 것은 사용자 몫이다 |
