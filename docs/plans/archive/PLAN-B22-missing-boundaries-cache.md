# PLAN-B22 · 경계 캐시가 없는 job 처리 — FAILED 안내 · DONE인데 캐시 없음 · extract-v2 캐시 미스 감지

> 출처: `docs/TODO.md` §9(REQ-B19 미결 3건 이관, 2026-09-29 사용자 결정) + 2026-09-30 세션 코드 확인 · 작성: 2026-09-30 · 상태: ✅ 완료 (PR #26 main 머지 `f18c495` · dev 확인 2026-09-30)

## 배경

B19(계약 #34)로 조회 엔드포인트는 경계 캐시가 없으면 **감지하지 않고 빈 결과**를 준다. 30초 504와 감지 누적은 이걸로 막았다.
다만 "캐시 없음"이 드러나는 곳 세 군데가 정리되지 않은 채 남았다. 원인은 하나다 — **경계 캐시가 없는 job을 어떻게 보여 주고 어떻게 다시 채우는가.**

1. **FAILED 파일이 "문항 0개"로만 보인다.** 2026-09-29 dev 확인 때도 그랬다(사용자 육안: "상세진입 됨, 문항 0개, 문서 미리보기 이상 없음").
   왜 0개인지, 재감지하면 된다는 안내가 없다. 작업 화면 진입 차단 모달(`useAnalysisEntryGuard`, REQ-F11)의 `reason`은
   `processing`·`unavailable` 두 가지뿐이고, FAILED는 막지 않는다.
2. **`DONE`인데 경계 캐시가 없는 job**(캐시를 지운 경우 등)도 조용히 0문항이 된다. 이런 job이 실데이터에 있는지는 확인하지 않았다.
3. **extract-v2 Step 2의 캐시 미스 감지**(`pdf_service`) — 선택된 job의 캐시가 없으면 백그라운드에서 `detect_question_boundaries`를 돌리고
   캐시를 저장한다. 요청 경로는 아니지만 **B17 동시 분석 한도(`analysis_slots.slots`, 5개) 밖**에서 돈다. 큰 PDF가 겹치면 B17이 막은 OOM이 이 경로로 다시 열린다.
   이 감지는 상태 파일(`boundaries_status`)도 갱신하지 않는다.

## 범위

**포함**
- FAILED(그리고 2가 해당되면 캐시 없는 DONE) job의 작업 화면 안내
- DONE인데 캐시 없는 job의 실데이터 조사와 처리
- extract-v2 캐시 미스 감지를 B17 한도 안으로 넣거나 없애기

**제외**
- 조회 엔드포인트에서 감지 되살리기 — 계약 #34가 막는다(B19에서 없앤 경로)
- 기존 job의 경계 캐시 일괄 재생성·마이그레이션 — 재감지 버튼이 그 역할이다(B21과 같은 방침)
- v1 `/api/extract`의 매번 감지(한도 밖) — 프론트가 호출하지 않는 경로라 `docs/TODO.md`로 넘긴다(2026-09-30 사용자 결정)
- 진입 차단 모달(`useAnalysisEntryGuard`) 변경 — FAILED는 계속 진입을 허용한다(결정 표)

- 계약 #34: 조회 엔드포인트는 감지를 돌리지 않고 상태 파일도 쓰지 않는다 — 안내는 **이미 있는 상태**(`boundaries_status`·`error`)를 읽기만 한다
