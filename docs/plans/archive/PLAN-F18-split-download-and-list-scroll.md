# PLAN-F18 · 생성 화면에서 다운로드를 걷어내고, 진입 시 페이지 목록을 보이게 한다

> 출처: 2026-10-05 dev 육안(사용자) · 작성: 2026-10-05 · 상태: ✅ 완료 2026-10-05 (`/review` 2회차 · **dev 육안 3건 확인**)

## 배경

**둘 다 2026-10-05 dev 확인에서 사용자가 지적한 것**이고, 성격은 다르다.

**1. 생성 화면이 "만드는 곳"과 "받는 곳"을 겸하고 있다.**
REQ-F16 이 "클릭 한 번으로 저장"을 만들면서 생성 화면에 저장 위치 선택 창·다운로드 버튼이 들어왔다.
쓰고 보니 **업무가 섞였다** — 사용자 표현으로 *"생성은 PDF 를 만드는 곳, 결과는 만들어진 걸 다운로드 하는 곳"*.
F16 이 틀렸다기보다 **화면의 역할 분담을 그때 정하지 않은 것**이다.

**2. 현황판에서 페이지 번호로 진입하면 그 페이지가 목록에 안 보인다.**
REQ-F12 아코디언에서 `?page=` 로 들어오면 **뷰어는 그 페이지로 간다**(REQ-B25 가 고쳤다).
그런데 **왼쪽 페이지 목록은 맨 위에 그대로** 있어서, 212쪽 문서에서 150쪽으로 진입하면
"지금 몇 쪽을 보고 있는지"가 목록에서 안 보인다. **B25 의 짝이 되는 자리인데 빠져 있었다.**

## 범위

**포함**
- 생성 화면(`editor/index.jsx`)에서 **다운로드를 통째로 제거** — 저장 위치 선택 창·다운로드 버튼·저장 에러 표시·관련 상태
- 완료 Alert 은 **문구 + `[결과로 이동]` 버튼**으로 바꾼다 (`paths.results` — 메뉴 이름이 "결과"다)
- 작업 화면(`analysis/work.jsx`) **페이지 목록**이 `?page=` 진입 시 **선택된 항목을 목록 가운데로** 스크롤

**제외**
- **결과 화면(`history/index.jsx`)의 저장 위치 선택 창은 유지** — 2026-10-05 사용자 결정 *"결과 - 다운로드 경로 선택 창은 유지"*.
  거기가 "받는 곳"이므로 F16 Phase 2 가 만든 **창 먼저 열기·취소/미지원/실패 3분기**는 그대로 산다
- **`utils/savePdf.js` 는 건드리지 않는다** — 결과 화면이 계속 쓴다. 순수 함수 케이스(F16-01~12·14·15·17·20·23)도 그대로 유효하다
- **목록 클릭·뷰어 역동기화로 선택이 바뀔 때의 스크롤** — 2026-10-05 사용자가 범위를 *"현황판에서 페이지 번호 클릭하는 진입 플로우에서만"* 으로 좁혔다.
  ⚠️ 이게 **설계를 단순하게 만든 결정**이다 — 아래 § 제약·함정 참조
- 결과 화면의 UI 변경 · 생성 이력 자동 이동(완료 시 화면 전환) — 사용자가 **버튼**을 원했지 자동 이동을 원한 게 아니다

## 제약·함정

- ⚠️ **"선택되면 스크롤"로 짜면 안 된다.** `work.jsx` 에서 `selectedPage` 가 바뀌는 경로가 **셋**이다 —
  목록 클릭(`handlePageClick`) · **뷰어 스크롤 역동기화**(`handleViewerPageChange`, 250ms 디바운스) · 복원.
  선택 변경을 트리거로 삼으면 **사용자가 뷰어를 스크롤할 때마다 왼쪽 목록이 제멋대로 끌려간다.**
  진입 effect 안에서만 스크롤할 것 — **B25 의 `pendingScrollRef` 와 같은 결**이다.
  ⚠️ **그 effect 자체가 1회가 아니다** — `pages` 가 deps 인데 **재감지 완료가 `fetchPages` 를 다시 부른다**(`onDone`).
  배열 정체성이 바뀌어 effect 가 재실행되므로, 이미 처리한 키를 ref 에 들고 걸러야 한다(F18-10). (`/review` 회차 0 의 (b))
- **이 목록은 가상화가 아니다** — 212개 항목이 전부 렌더되므로 계약 #7(가상화 `scrollToPage` 의 0px 누적) 은 **여기 안 걸린다.**
  B25 와 증상이 비슷하다고 같은 해법을 끌어오지 말 것
- ⚠️ **`scrollIntoView` 는 스크롤 가능한 조상을 전부 스크롤한다.** 이 앱은 100dvh 작업대라(계약 #1)
  바깥이 스크롤되지 않는 게 정상이지만, 체인이 깨지면 **페이지 전체가 함께 움직인다.**
  컨테이너 기준 계산(`container.scrollTop`)이 더 안전한지는 구현에서 판단한다
- **jsdom 에는 레이아웃이 없다** — `scrollIntoView` 는 스텁이고 실제 스크롤 위치는 **테스트로 검증할 수 없다**(B25·F17 과 같은 구조).
  케이스는 "진입 경로에서만 불린다 / 선택 변경에서는 안 불린다"까지만 덮고, **가운데에 오는지는 dev 육안**이다
- **`editor/index.jsx` 는 렌더 무대가 없다**(API mock 5~6개 필요). 소스 스캔 테스트는 **JSX 를 컴파일하지 않으므로**
  케이스가 전부 녹색이어도 문법 오류를 못 잡는다 — **`npm run build` 를 따로 돌린다**(CLAUDE.md 진행 현황 절)
- **폐기되는 F16 케이스를 조용히 지우지 말 것** — F16-13·16·18·19·21·22·24·25·26·29·30 이 생성 화면 다운로드를 고정한다.
  전제가 사라졌으므로 **폐기하고 그 사실을 F16 계획서에 남긴다**(REQ-F17 이 B12-02·03 을 폐기할 때와 같은 처리)
